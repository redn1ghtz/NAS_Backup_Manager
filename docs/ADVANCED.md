# Дополнительные возможности — тестовая portable-сборка

Portable preview `0.2.0-alpha` от 24 октября 2026. Установщики и опубликованный релиз
`0.1.0-alpha` не обновляются до отдельного одобрения.

## Где настроить

При создании или изменении задачи откройте шаг «Расписание и архив» →
«Дополнительные возможности». Политики и выбор каналов независимы для каждой задачи; параметры Telegram/SMTP общие и задаются в разделе «Настройки» программы.
Перед изменением действующей задачи выключите её расписание. После сохранения
снова проверьте preview: новое расписание активируется после успешной синхронизации.
Для основного облачного назначения выберите «Облачное хранилище» на шаге назначения.
Указанная локальная папка в этом режиме — рабочий кэш, облачная папка задаётся отдельно.

## Целостность: SHA-256

Для каждого нового/заменённого файла сохраняется контрольная сумма **записанной
копии**, независимо от включения периодической проверки. После записи выполняется
сравнение прочитанной копии с хешем переданных байтов.

Периодическая проверка выключена по умолчанию. При включении она выполняется
перед следующей синхронизацией после заданного интервала (по умолчанию 7 дней).
Это работа в headless-процессе задачи, а не постоянно работающая служба.
Проверяются актуальные файлы, локальный архив и ранее успешно выгруженные облачные
файлы по локально сохранённым SHA-256. Облако проверяется потоковым скачиванием;
такая проверка расходует трафик. Лимит чтения по умолчанию — 8 МиБ/с.

Старые копии без эталонной суммы нельзя объявлять исправными только по их чтению.
Для них исходная сумма устанавливается лишь при совпадении с доступным источником.
Если старый источник уже отличается, файл остаётся без доверенного эталона до
следующего успешного копирования. Несовпадение с уже сохранённой суммой — ошибка
целостности; повреждённые данные не удаляются и не «исправляются» молча.
Ручной запуск: меню «…» задачи → «Проверить целостность».

MD5 не используется: единый SHA-256 упрощает хранение и исключает слабый алгоритм.
Проверка обнаруживает изменение байтов, но не является диагностикой физических
секторов и не обеспечивает согласованный снимок открытой базы данных.

Проверка на главной показывает число обработанных файлов, прочитанные байты,
процент и приблизительное оставшееся время. Значение скорости `0` отключает
ограничение чтения как для ручной, так и для периодической проверки.
Для отдельной облачной фазы точный процент пока не вычисляется.

## Повторы и скорость

По умолчанию: 3 повтора, задержки 2, 4, 8 секунд, максимум 60 секунд.
Повторяются временные ошибки соединения. Нет бесконечных попыток при запрете
доступа или заполненном диске. Обычное потоковое копирование может продолжить
с последнего полностью записанного буфера: неполный буфер отбрасывается,
идентичность файлов перепроверяется. Уже завершённые файлы сохраняются.
Проверки доступности также допускают безопасный повтор; переименование и удаление
не воспроизводятся вслепую при неопределённом результате операции.

Для age поток шифрования не возобновляется посередине: при сбое требуется новый
запуск конкретного файла. Повторы облачных операций выполняет rclone с внешней
экспоненциальной задержкой для временных ошибок; докачка внутри файла зависит от
провайдера. При падении процесса не обещается продолжение произвольного файла с байта.

Ограничение копирования по умолчанию 0 (без ограничения). Можно задать КиБ/с и
местный интервал, включая переход через полночь. Одинаковое начало/окончание —
весь день. Ограничение действует на новые копии, архивирование и облачную передачу.
Проверка целостности имеет отдельный лимит чтения.

## Сквозное шифрование age

Используется стандартный формат и официальный инструмент [age](https://age-encryption.org/),
а не самостоятельно разработанная криптосхема. Нужен публичный ключ получателя
`age1…`; приватный ключ для самого резервного копирования не требуется.
Шифрование выполняется на клиенте до записи на NAS/диск и до отправки в облако.
Локальный кэш облачного бэкапа при включённом age тоже содержит шифротекст.
Имена файлов, размеры и времена изменения не скрываются.

В форме задачи откройте «Дополнительные возможности» → «Шифрование · age» и
нажмите «Создать ключи и сохранить файл восстановления». Выберите новое имя файла
`backup-recovery.agekey` в защищённом месте (например, на флешке). Публичный ключ
подставится автоматически, закрытый будет подготовлен для защищённого хранения
при сохранении задачи. Существующий файл ключа не перезаписывается. Отмена диалога
не меняет настройки. Пока публичный ключ заполнен, повторная генерация отключена.
Файл восстановления содержит закрытый ключ в открытом виде: защищайте носитель
и не отправляйте этот файл другим людям. Для отключения шифрования очистите поле
публичного ключа; старые ключи сохраняйте для ранее зашифрованных копий.

Ручной вариант в PowerShell из папки тестового приложения:

```powershell
.\tools\age-keygen.exe -o "$env:USERPROFILE\backup-recovery.agekey"
.\tools\age-keygen.exe -y "$env:USERPROFILE\backup-recovery.agekey"
```

Второй вызов выводит публичный ключ: вставьте его в задачу. Закрытый файл
импортируется отдельной кнопкой и сохраняется приложением через DPAPI. Исходный
файл импорта не удаляется. Сохраните его независимую защищённую резервную копию
вне NAS и portable-папки. Без закрытого ключа расшифровка невозможна.

У зашифрованной версии в архиве есть отдельная кнопка «Расшифровать файл» для
экспорта в выбранную папку, в том числе после удаления задачи.
Восстановление из архива возвращает сохранённую версию в текущую копию, сохраняя
её зашифрованный формат. Для получения обычного файла: меню «…» → «Расшифровать
файл», относительный путь и отдельная выходная папка. Существующий файл не
перезаписывается. Для восстановления после утраты приложения можно использовать
обычный `age --decrypt --identity <ключ> --output <новый-файл> <зашифрованный-файл>`.

При изменении публичного ключа **сохраните все старые приватные ключи** для архива.
Можно импортировать identity-файл с несколькими строками AGE-SECRET-KEY.
Автоматической миграции уже существующего незашифрованного архива нет:
включение age для такой задачи блокируется с понятной ошибкой; используйте новую
задачу/назначение и сохраните старый архив отдельно. При отсутствии старого архива
включение age у существующей задачи переупакует актуальные файлы при следующем запуске.

## OneDrive и Dropbox

При выборе облачного назначения после шага «Назначение» появляется отдельный
шаг «Облачное хранилище». Для дополнительной облачной копии включите соответствующий
пункт на шаге назначения: настройка облака также появится отдельным следующим шагом.

1. Выберите OneDrive или Dropbox.
2. Нажмите «Подключить аккаунт», войдите в открывшемся системном браузере и разрешите доступ.
3. Укажите отдельную папку в облаке, например `Backups/Documents`.
4. Продолжите настройку расписания, сохраните задачу и проверьте предпросмотр.

Не нужно создавать проект разработчика, JSON OAuth, конфиг rclone или пароль:
программа сама создаёт зашифрованный конфиг и подставляет все служебные пути.
Случайный пароль конфигурации хранится через DPAPI, секреты не возвращаются в форму.
Авторизация ограничена пятью минутами и может быть отменена. Отмена не запускает бэкап.

Используются штатные OAuth-клиенты rclone. В OneDrive настраивается Personal/Business
и выбирается первый доступный диск аккаунта; настройка SharePoint не предлагается.
Если рабочая учётная запись запрещает сторонние приложения, потребуется разрешение
администратора. Ограничения тарифа, квоты API, отзыв доступа и правила провайдера
остаются в силе. Повторный вход может понадобиться при отзыве доступа; обязательного
семидневного тестового периода настройки приложения нет.

Проверено по документации 23.10.2026: стандартные client ID/secret rclone для
[OneDrive](https://rclone.org/onedrive/) и [Dropbox](https://rclone.org/dropbox/)
не требуют регистрации приложения пользователем. Для фоновой работы используются
refresh token. [Dropbox OAuth](https://docs.dropboxapi.com/dropbox-api/docs/oauth)
поддерживает offline access и обновление короткоживущих access token.
[Microsoft](https://learn.microsoft.com/en-us/entra/identity-platform/refresh-tokens)
описывает обновление refresh token при использовании и возможность отзыва доступа.
Повторный вход возможен при истечении/отзыве токена или политике организации.
Общий клиент не отменяет ограничений API: OneDrive может ограничивать частоту
запросов, а рабочая учётная запись — требовать разрешение администратора.
Живая загрузка в эти сервисы в этой проверке не выполнялась.


Облачная папка должна быть новой или пустой при первом подключении. Программа
добавляет маркер владения и отказывается изменять чужое назначение. Корень аккаунта
не используется. Данные копируются односторонне. В основном облачном режиме нужен
локальный кэш размером с резервную копию; при age он также содержит шифротекст.

Во время облачной передачи rclone публикует фактические байты, число файлов и ETA
раз в 500 мс; данные сохраняются локально, поэтому повторное открытие интерфейса
подхватывает текущую передачу. Отправка архива выделена отдельной фазой. Процент
ограничен 99 до завершения процесса; при неизвестном объёме/скорости оценка не выдумывается.
Парсер ограничен строкой 64 КиБ и одним последним образцом, сырые журналы не сохраняются.

Квота показывается на главной только для включённого облачного назначения выбранной
задачи. Запрос ограничен кэшем на пять минут; постоянного опроса облака нет.
В заголовке указано подключённое облако: Dropbox или OneDrive.
Главная подстраивает высоту списков под окно; задачи и последние операции
прокручиваются внутри своих блоков, без прокрутки всей главной страницы.
Операции в предпросмотре и истории: новые — зелёные, изменённые — жёлтые,
удаляемые — красные; текстовые названия сохраняются.
Облако показано первым: круг с процентами, использовано/свободно/всего; ниже — локальный диск или кэш. Кнопка обновления запрашивает свежие данные без кэша.
После входа в браузере программа дополнительно проверяет чтение списка файлов.
Успешная авторизация сама по себе не подтверждает доступность файлового API.
Ранее созданные неподдерживаемые подключения не удаляются и не переназначаются автоматически: выберите поддерживаемое облако и подключите аккаунт заново. Локальные и удалённые копии сохраняются.
Если API не предоставляет квоту или запрос недоступен, показано «недоступно».

Облачные версии удалённых файлов не очищаются автоматически в этой тестовой сборке.
Не удаляйте старый архив до проверки восстановления и срока хранения.

Документация адаптеров: [OneDrive](https://rclone.org/onedrive/),
[Dropbox](https://rclone.org/dropbox/).

## Telegram / SMTP и защита секретов

Общие параметры аккаунтов задаются в «Настройки» → «Telegram и почта». В задаче
остаются только два переключателя, включающие отчёты после завершения запуска:
имя задачи, локализованный результат, объём в Б/КБ/МБ/ГБ/ТБ и длительность, а также
дата и время окончания конкретного запуска с часовым поясом. Язык берётся из настроек
приложения при отправке. Тема письма содержит название задачи и «успешно»/«не завершено»;
В Telegram отчёт начинается с жирного «NAS Backup Manager», затем после пустой строки
следуют поля с жирными подписями и обычными значениями. Имя задачи безопасно экранируется
для HTML-разметки Telegram. Длительность: «0 ч 0 мин 12 с» (на английском «0 h 0 min 12 s»).
Письма имеют такое же жирное оформление заголовка и подписей; тема с названием задачи
и результатом сохраняется. Добавлена текстовая версия для почтовых клиентов без HTML.
Кириллическая тема письма кодируется по RFC 2047.
Содержимое файлов и список
путей не отправляются. Telegram требует bot token и chat ID; SMTP — сервер,
логин, пароль приложения, адрес отправителя и получателя.
Для SMTP обязательны TLS/STARTTLS и стандартная проверка сертификата.
Отключать проверку сертификата настройки не позволяют. Доставка каждого отчёта
ограничена 30 секундами, ошибки фиксируются отдельно от результата копирования.
Переключатель Windows-уведомлений управляет только системными toast-сообщениями;
Telegram и SMTP включаются отдельно на задаче.

Токены, пароль SMTP, пароль конфигурации rclone и импортированные приватные age-ключи:

- не записываются в SQLite, журнал, аргументы командной строки или ответы чтения задач;
- сохраняются в `data/secrets/*.dpapi`, зашифрованных Windows DPAPI CurrentUser;
- передаются помощникам через stdin либо окружение короткоживущего процесса;
- не входят в portable-дистрибутив и файлы публикации;
- недоступны на другом ПК/профиле без повторного ввода/импорта.

Старые задачи используют прежние параметры, пока соответствующий общий канал не
настроен. В настройках доступен явный импорт из выбранной задачи: он переносит
включённые в ней каналы, сохраняя остальные общие каналы и все данные/расписания задач.
Общие изменения получателей действуют для всех задач с включённым каналом.
Метаданные профиля и ссылка на зашифрованный blob хранятся в SQLite; токен и пароль —
только в отдельном DPAPI blob. Изменение SQLite ссылки выполняется после успешной
записи нового blob, старый остаётся доступен читающим процессам.

Пустое поле секрета при редактировании оставляет прежнее значение. Программа
не возвращает сохранённые значения в форму. Закрытый ключ и OAuth-секреты
расшифровываются в памяти только когда нужны соответствующей операции.
Защита предполагает доверенный клиентский ПК и профиль Windows. Она не защищает
от вредоносного ПО, уже выполняющегося с правами этого пользователя.
На Linux/macOS защищённое хранилище пока не реализовано: операции с секретами
отказывают, небезопасного сохранения открытым текстом нет.

## Нагрузка и проверенные пределы

Нет нового сервиса, непрерывного сканирования NAS, постоянных облачных запросов
или запросов к Telegram/SMTP в простое. Файловые буферы — 256 КиБ. Метаданные
SHA-256 записываются пакетами до 128 записей; транзакция не удерживается во время
сетевого копирования. rclone запускается только для работы/квоты, с одним transfer
и checker, буфером 1 МиБ, пределом буферов 32 МиБ и очередью 128.
Эти параметры ограничивают ресурсы реализации, а не число файлов/задач.

Автоматические тесты используют временные папки. Для age и rclone выполнены
интеграции с одноразовыми ключами и локальным alias-remote. Реальные аккаунты
OneDrive/Dropbox и реальная доставка Telegram/SMTP без пользовательских
учётных данных не проверялись. Native 32-bit Windows, Linux и macOS отдельно
не подтверждены; x86 проверяется в WOW64 на Windows 10 x64.
