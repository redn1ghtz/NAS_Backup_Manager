# NAS Backup Manager — пользовательский сценарий

1. Запустите EXE из `portable/NAS Backup Manager/`. Флаг `portable.flag` хранит
   настройки и журнал в соседней `data/`, без установки и регистрации автозапуска.
2. «Добавить задачу»: имя и источник → локальная или сетевая папка → расписание и
   режим архива → проверка. Папки должны уже существовать. NAS подключается ОС.
3. Новая задача пишет файлы непосредственно в выбранную **пустую** папку назначения:
   `ddd/файл.txt`, без ID задачи и `current` в пути данных. Служебная
   `.nas-backup-manager` внутри неё хранит архив, staging, блокировку и метку
   владельца; она исключена из зеркалирования. Выбранная папка становится зеркалом
   источника; вручную добавленные в неё посторонние файлы попадают под правила
   удаления этой задачи. Существующие задачи используют прежний формат и остаются
   на месте. Автоматического переноса или удаления их копий/архивов нет.
4. После сохранения откроется preview. Проверьте действия, особенно удаления,
   предупреждение о массовом удалении и файлах БД; поставьте флажок согласия.
   Если файлы изменились, нужно сформировать новый план. План годен 15 минут.
5. Первый успешный запуск разрешает дальнейшее включение расписания. Включение
   расписания требует отдельного подтверждения; до него автоматического копирования нет.
6. «Архив»: выберите задачу (в том числе удалённую), версию и «Восстановить».
   Восстановление идёт в **активное зеркало**, не в источник. При коллизии нужно
   подтвердить архивирование существующего файла перед заменой. Если он изменится
   после подтверждения, операция снова блокируется. Исходная архивная версия остаётся.
7. «Удалить истёкшие версии» — необратимая очистка с подтверждением. Плановый
   запуск очищает истёкшие версии после успешного копирования. Версии из незавершённых
   или проваленных исходных запусков не истекают автоматически. Смена N дней
   применяется к новым версиям; даты уже созданных версий не переписываются.
8. Выключите расписание перед изменением задачи, удалением или переносом папки
   приложения. Удаление задачи скрывает конфигурацию из активных задач; архив остаётся
   доступным через выбор задачи в «Архив». Каталог контейнера остаётся защищённым
   от повторного использования пересекающейся задачей.

«Приостановить» отключает будущие плановые запуски; это не отмена уже работающего
процесса. Чтобы остановить текущую синхронизацию, на главной нажмите «Отменить»
рядом с прогрессом. Кнопка работает и для планового запуска после открытия окна.
До безопасной остановки показано «Отмена…»: текущая операция ОС или архивирование
может потребовать времени. Завершённые копии и архив остаются, собственный
незавершённый временный файл удаляется; уже выполненные изменения не откатываются.
Результат «Отменено» не считается ошибкой. Расписание сохраняется, очистка архива
после отменённого запуска не выполняется. Для повторного ручного запуска нужен
новый preview. После редактирования снова требуется успешный ручной preview/запуск.
Настройки источника/контейнера существующей задачи неизменяемы для защиты архива:
для другой пары путей создайте отдельную задачу.

Символические ссылки/junction, специальные файлы и конфликты файл ↔ каталог
останавливают планирование. Нечитаемый/отключённый источник не считается пустым.
Задания не создают согласованные снимки открытых баз данных. Перед копированием
такой БД закройте использующее её приложение или применяйте штатный экспорт.

Windows: Task Scheduler запускает CLI в сеансе текущего вошедшего пользователя.
Пароль учётной записи Windows для расписания не сохраняется. Пробуждение настраивается в задаче; запрет сна не включается. Сетевые диски должны
быть доступны именно этому пользователю. Пропущенные запуски выполняются один раз
при доступности, если выбран такой режим. Linux-адаптер требует systemd user;
при его отсутствии используйте внешний планировщик с командой:

`nas-backup --state /absolute/path/state.sqlite run-scheduled JOB_UUID`

macOS использует launchd. Linux/macOS пока не проверены на реальных системах;
launchd может объединять запуски после сна независимо от политики пропуска.
Проверки на настоящем NAS и съёмных дисках, аварийном отключении питания и всех
вариантах DST ещё нужны. Исчерпывающей гарантии восстановления после аварии нет:
проверяйте «Журнал»; файлы staging/pending не удаляются автоматически по предположению.

На macOS сетевое назначение пока блокируется, если идентичность mount/share
не может быть установлена безопасным адаптером. Локальные функции требуют отдельной
проверки на macOS. На Windows тип Network требует доступного UNC-ресурса (включая
разрешённый ОС путь подключённого диска); обычная локальная папка под видом NAS
не принимается. На Linux распознаются сетевые файловые системы через mountinfo.

Журнал обычных запусков ограничен последними 1000 запусками на задачу, кроме
записей, на которые ссылается защищённый архив. Аудит восстановления/очистки хранит
10000 последних событий. Эти ограничения относятся только к истории UI, а не к
числу задач, файлов, операций копирования или версиям неистёкшего архива.


## Гибкое расписание и архив

В задаче можно выбрать ежедневное время, каждые N минут (1–44640),
каждые N часов (1–744) или каждые N дней (1–365) в местное время.
Диапазоны соответствуют возможностям Windows Task Scheduler
([интервалы](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-interval-repetitiontype-element),
[дни](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/schtasks-create)).
Дневной цикл отсчитывается от местной даты сохранения задачи и не сбрасывается
на границах месяцев. Редактирование начинает новый цикл и отменяет предыдущее
разрешение на автоматическую работу. Интервальный триггер впервые срабатывает
примерно через минуту после включения, затем повторяется с выбранным интервалом.
Перекрывающиеся запуски не выполняются; пропущенные интервалы не образуют очередь.

Windows использует календарные/повторяющиеся триггеры Task Scheduler.
Linux: systemd user, интервалы через OnUnitActiveSec; дневные режимы — календарный
таймер. Для N дней headless CLI проверяет дату в SQLite и в промежуточные дни
не обращается к источнику/NAS. Интервальные таймеры systemd не сохраняют пропущенные
монотонные интервалы между перезагрузками; после включения отсчёт начинается заново.
macOS: launchd StartInterval/StartCalendarInterval с такой же проверкой дневного
цикла. Семантика сна и пропусков зависит от ОС; Linux/macOS не проверены на машине.
Постоянного процесса и сканирования в простое нет. Проверка даты N дней использует
местные календарные дни, а не фиксированные сутки по 24 часа. Полные DST-тесты нужны.

Режим архива:
- **Хранить N дней**: предыдущие копии архивируются перед заменой/удалением.
- **Не хранить — удалять сразу**: прежние копии в активном зеркале удаляются
  без создания новых архивных версий. Источник не удаляется. Preview явно
  предупреждает об отсутствии восстановления; флажок подтверждает именно этот
  режим. Автоматизация разрешается после успешного ручного запуска и отдельного
  включения расписания. Каждый плановый запуск не требует нового вопроса.

Смена режима на «не хранить» не стирает старый архив. Уже созданные версии доступны
для восстановления и истекают в изначальные даты. При подтверждённом восстановлении
поверх существующего файла его копия по-прежнему сохраняется в архив: это отдельная
явная операция «архивировать и заменить», описанная в диалоге коллизии.
Отключение архива не отключает защиту от неправильного диска, неполного сканирования,
устаревшего preview, массовых удалений и неудачной подготовки новой копии.

## Данные на главной

Компоновка сверена с design-reference.png: задачи и ёмкость справа, затем последняя
синхронизация, архив, расписание и последние файловые операции. Ёмкость обновляется
при открытии главной, выборе задачи, завершении синхронизации и возвращении фокуса
в окно. Кнопка «Обновить состояние» сохраняется. Постоянного опроса NAS нет. Это ёмкость всего тома/ресурса,
а не размер только резервных копий. Фиктивной квоты архива нет.

Количество и байты новых/изменённых/удалённых файлов берутся из завершённых действий
движка, длительность — из времени запуска/окончания. При старых запусках без сводки
показывается «—», а не выдуманные показатели. Отдельное время сканирования не
показывается: ранее оно не измерялось. Preview не заменяет последнюю синхронизацию.
Частично выполненный/прерванный запуск не считается успешным; неподтверждённые
счётчики после сбоя могут быть неполными.

Архив показывает число проверенных версий, их объём и ближайшее истечение для
выбранной задачи. Журнал содержит два представления: файловые операции и запуски,
восстановления, очистку. Метаданные последних 1000 файловых действий на задачу
сохраняются независимо от preview; главная выводит 20, журнал — 50 на страницу.
Время файлового события — время фиксации итогов запуска. Ограничение истории
не ограничивает копирование или сохранность неистёкших архивных версий.
Пагинация использует компактные < и > с доступными названиями RU/EN.


## Автоматический вход в NAS на Windows

В шаге выбора сетевого назначения или кнопкой **Доступ к NAS** у существующей
задачи введите UNC-путь, имя пользователя NAS (`NAS\user`, `DOMAIN\user` либо имя
локального пользователя NAS) и пароль. Нажмите **Подключить и сохранить**.
Используется подключение SMB средствами Windows, без собственного SMB-протокола.
После перезагрузки открывать ресурс в Проводнике перед бэкапом не требуется:
GUI и headless CLI используют один адаптер подключения перед операцией.

Пароль хранится как отдельная запись текущего пользователя в Windows Credential
Manager (Generic / Local Machine persistence), а не в SQLite/настройках portable.
Запись привязана к серверу и имени ресурса; подходит для других подпапок этого же
ресурса. Секрет передаётся системному адаптеру по stdin, не через командную строку,
файлы или журнал приложения; текст исключений адаптера не возвращается в UI.
Штатные ошибки преобразуются в краткие коды. UI не загружает сохранённый пароль.
Кнопка **Проверить сохранение** проверяет наличие записи, не доступность сервера.
**Забыть учётные данные** удаляет только запись приложения, не разрывает открытые
подключения других программ. На другом ПК/под другим пользователем настройте
доступ заново: portable-папка не переносит защищённое хранилище Windows.

По возможности используется уже доступный сеанс Windows. Если папка недоступна,
адаптер читает сохранённую запись и вызывает WNetAddConnection2. Без записи
пробуется контекст Windows/домена. Таймаут системного помощника — 30 секунд,
автоматических бесконечных повторов нет. При конфликте учётных записей Windows
(1219) приложение показывает ошибку, не отключая чужие сеансы принудительно.
Это не отменяет проверку ожидаемого диска/ресурса и меток владения перед изменениями.

Планировщик запускает CLI в сеансе вошедшего пользователя Windows. Полностью
закрытый GUI поддерживается; запуск до входа пользователя в Windows этим режимом
не обеспечивается. Сон/выключенное питание NAS/недоступная сеть обрабатываются
по настройкам пропусков и видимым ошибкам. Реальная проверка после перезагрузки
с вашим NAS нужна отдельно; текущие тесты не перезагружали пользовательский ПК.
Linux/macOS продолжают использовать подключения и секреты средствами ОС;
встроенная форма сохранения учётных данных предназначена для Windows.

Адаптер использует встроенные PowerShell/.NET и Win32 Credential/Network API.
Постоянной службы нет: помощник запускается только для явной операции/планового
срабатывания, завершается после ответа и не вызывается для каждого файла.
При ограничительных политиках PowerShell/Add-Type будет показана ошибка адаптера.
Документация Microsoft: [WNetAddConnection2](https://learn.microsoft.com/en-us/windows/win32/api/winnetwk/nf-winnetwk-wnetaddconnection2w),
[тип и срок хранения Credential](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw).

## Отображение и состояния

Служебные префиксы `\\?\` и `\\?\UNC\` скрыты только при отображении путей;
движок по-прежнему использует полные пути для длинных имён. Приветствие зависит
от местного времени: ночь 23–06, утро 06–12, день 12–18, вечер 18–23. Оно
обновляется на границе часа и при возвращении к окну, без частого опроса.
Числа в расписании/архиве используют RU/EN plural rules, включая 11–14 и 21/22.
Общие значки состояний: зелёная галочка — выполнено, синяя информация — архив,
серая информация — без изменений, красный знак — ошибка, часы — выполнение.


## Гостевой доступ без пароля

В «Доступ к NAS» выберите **Способ подключения → Использовать гостевой доступ —
без пароля → Сохранить режим**. Вводить `guest` вручную и заполнять пароль не надо.
Для нового подключения используется имя `guest` с явно пустым паролем (не пароль
текущего пользователя Windows). Режим сохраняется для ресурса в Windows vault,
читает его и CLI планировщика. Он восстанавливается при повторном открытии настроек
существующей задачи; «Проверить сохранение» также перечитывает выбранный режим.
Сохранение настройки не требует, чтобы NAS был сейчас онлайн: доступ проверится
при preview/запуске. Сохранение режима не является подтверждением успешного входа.

Другие варианты: «Автоматически — учётные данные Windows» (удаляет профиль
приложения для ресурса) и «Имя пользователя и пароль NAS» (как раньше).
Наличие доступного сеанса Windows не приводит к его принудительному разрыву.
Гостевой вход должен разрешаться сервером и политикой Windows. Приложение не
включает небезопасный гостевой SMB и не отключает подпись/шифрование автоматически.
Ошибка блокировки Windows и отказ NAS от гостевого входа показываются отдельно.
См. [документацию Microsoft](https://learn.microsoft.com/en-us/windows-server/storage/file-server/enable-insecure-guest-logons-smb2-and-smb3).


## Защита от массового удаления

В добавлении/редактировании задачи, шаг 3 «Расписание и архив», доступны включатель
защиты и минимальное количество удаляемых файлов (целое число от 1). По умолчанию
защита включена, порог — 10 файлов; эти значения получают и существующие задачи.
Проценты не используются: при пороге 10 удаление 1 из 2 или 9 файлов разрешено,
удаление 10 и более останавливает автоматический запуск с ошибкой в журнале.
Окно подтверждения при фоновом запуске не появляется. Такой план можно проверить
и подтвердить вручную в предпросмотре. Обновлённые файлы не считаются удалёнными.

При отключении защиты количество удалений не блокирует запуск. Режим архива
независим: «Не хранить» удаляет копии навсегда. Доступность источника, полнота
сканирования, идентичность назначения и блокировки проверяются при любом режиме.
Для изменения действующей задачи сначала отключите её расписание. После сохранения
проверьте и выполните новый план вручную, затем снова включите расписание.

Ссылки на [автора](https://github.com/redn1ghtz) и
[проект](https://github.com/redn1ghtz/NAS_Backup_Manager) доступны в «О программе».


## Обновление результатов фоновых запусков

При открытом видимом интерфейсе раз в 5 секунд проверяется только счётчик изменений
локальной SQLite (`PRAGMA data_version`). При изменении перечитываются задачи и
сводка; время в «Моих задачах» обновляется вместе с последним результатом. NAS и
папки для этой проверки не сканируются. Проверка приостанавливается в скрытом
интерфейсе, возобновляется при возвращении; ручная кнопка обновления сохранена.

## Пробуждение и удаление задачи

На шаге 3 создания/редактирования есть «Будить компьютер для синхронизации».
По умолчанию выключено, включая существующие задачи. В Windows управляет
[WakeToRun](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-waketorun).
Для изменения выключите расписание, измените параметр, проверьте новый план,
затем включите расписание. Приложение не меняет системную схему питания.
Пробуждение зависит от поддержки оборудования и разрешённых таймеров; пользователь
должен оставаться в системе. Выключенный ПК не включается. Для Linux/macOS
управление пробуждением из приложения пока недоступно.

Регистрация Windows видна в корне «Библиотеки планировщика заданий» как
`NASBackupManager-<ID>`. Новые регистрации не скрываются. У старых регистраций
для изменения этого свойства выключите и включите расписание.

На главной и в «Задачах» откройте меню «…» у нужной строки → «Удалить задачу».
Подтвердите удаление. Сначала отключается её расписание, затем убирается задача
из активного списка. Копии и архив не удаляются; архив удалённой задачи доступен
в разделе «Архив». Если отключение расписания или блокировка не удались, ошибка
показывается в интерфейсе.

Фоновый `nas-backup.exe` в Windows собирается без создания консольного окна.
Результаты операций по-прежнему доступны в журнале приложения.


## Только вручную или автоматическое повторение

Шаг 3 → «Повторять» → «Только вручную» отключает расписание и пробуждение;
тумблер на главной выключен. Запуски выполняются через предпросмотр и кнопку
«Синхронизировать сейчас». У новых задач ручной режим выбран по умолчанию.

Для автоматической работы выберите ежедневный запуск или интервал в минутах,
часах либо днях. Сохраните задачу, проверьте план и подтвердите запуск: согласие
также разрешает включить выбранное расписание. После успешного копирования
приложение зарегистрирует задачу в планировщике и включит тумблер автоматически.
До этого показывается «Ожидает активации». При отказе от плана или ошибке копирования
расписание не включается. При ошибке регистрации копирование остаётся завершённым,
но интерфейс отдельно сообщает, что расписание включить не удалось.

Включённое повторение можно приостановить тумблером. Обычная ручная синхронизация
после такой паузы не включает его заново. Для перехода в ручной режим выключите
расписание, откройте «…» → «Изменить» и выберите «Только вручную».
Обновление приложения не активирует ранее выключенные расписания и не создаёт
новых заданий Windows для существующих задач без вашего действия.


## Прогресс, значок трея и уведомления Windows

При ручном или автоматическом запуске значок приложения появляется в трее.
Подсказка показывает имя задачи и процент, когда объём известен. При настоящей
ошибке значок меняется на красный и остаётся на 30 секунд; его можно скрыть через
контекстное меню. Сведения об ошибке остаются в журнале приложения.

Windows получает сообщения о начале, успешном завершении или ошибке запуска.
В «Настройки» → «Уведомления Windows» их можно отключить; по умолчанию они включены.
Изменение сохраняется для следующих запусков, в том числе без интерфейса.
Выключение во время фоновой работы учитывается перед уведомлением о её окончании.
Прогресс и значок трея продолжают работать. Windows может подавлять сообщения
собственными параметрами уведомлений и режимом фокусировки.

Приложение регистрирует свой ярлык в меню «Пуск» для идентификации уведомлений.
Это не автозапуск и не служба. Процесс значка существует только при синхронизации
и кратковременно после ошибки. Для плановых запусков используется планировщик ОС.

Открыв интерфейс во время планового запуска, вы увидите текущий файл, этап,
число обработанных файлов и объём передачи. Во время проверки файлов процент
не показывается, пока общий объём неизвестен. Данные берутся из локальной базы,
без повторного сканирования NAS. В простое опроса прогресса нет.

Изменение исходных файлов после предпросмотра показывается нейтрально:
«Файлы были изменены и будут обновлены при следующей синхронизации».
Копирование по устаревшему плану не выполняется: для немедленного запуска
получите новый предпросмотр. Настоящие ошибки доступа, архива или копирования
по-прежнему показываются как ошибки.


## Синхронизация при включении ПК

В шаге «Расписание и архив» выберите «Повторять» → «При включении ПК».
На Windows задача запускается через 30 секунд после входа в вашу учётную запись,
включая вход после включения компьютера. Открывать приложение не требуется.
Повторный вход после выхода из учётной записи также запускает задачу;
разблокировка сеанса и выход из сна сами по себе не являются таким запуском.
ПК и папка назначения должны быть доступны. Поля интервала, времени и пробуждения
для этого режима не используются. Следующий запуск обозначается как событие
«После следующего входа в систему», без вымышленной даты.
Как и другое расписание, режим включается после подтверждённого успешного
первого копирования. Существующие расписания при обновлении не меняются.
Linux: при старте пользовательского менеджера systemd (OnStartupSec=30s).
macOS: при загрузке пользовательского LaunchAgent (RunAtLoad). Эти варианты
на Linux/macOS отдельно не проверялись.

Прогресс синхронизации отображается компактным блоком только на главной странице. После подтверждения ручного запуска предпросмотр закрывается и открывается главная. В настройках и остальных разделах блок не показывается.


## Открытие интерфейса и точность прогресса

Для работы трея, уведомлений и открытия существующего окна рядом с основным EXE
и `nas-backup.exe` должен оставаться поставляемый `nas-backup-notify.exe`.
Программа проверяет его SHA-256 и не извлекает EXE в папку настроек. Неизменившийся
ярлык уведомлений и регистрация протокола при каждом бэкапе не перезаписываются.

Закрытие окна во время ручной синхронизации скрывает интерфейс, но копирование
и проверка продолжаются в том же процессе. Повторный запуск EXE, нажатие на
значок трея или уведомление возвращают это окно с текущим прогрессом. Если окно
не открывать, процесс интерфейса завершится после окончания работы. В простое
закрытие окна завершает интерфейс сразу; задания по расписанию отдельно запускает
планировщик ОС. Принудительное завершение процесса или выключение ПК прерывает
ручную операцию: такой запуск останется в журнале как прерванный, а новый
предпросмотр позволит безопасно повторить синхронизацию.

Один левый клик по значку трея открывает или разворачивает существующее окно.
Новые уведомления Windows также открывают интерфейс, в том числе после закрытия
процесса синхронизации. Для этого приложение регистрирует собственный локальный
протокол nasbackupmanager://open и ярлык уведомлений для текущего пользователя.
Протокол может только открыть интерфейс: адрес не используется как команда или
путь к файлу. Повторное открытие из уведомления использует то же окно.

Общий процент учитывает и копирование, и проверочное чтение записанных данных.
После передачи файла NAS может ещё сбрасывать данные на диск или читать файл
для проверки: эти этапы показываются отдельно. Активная операция не показывает
100% до успешного завершения. Примерное оставшееся время считается по недавнему
фактическому прогрессу, включая обработку многих небольших файлов. При долгом
сбросе на диск, отсутствии свежих данных, сканировании и завершении выводится
«Осталось: расчёт…», а не вымышленный точный срок.

Ёмкость хранилища можно прочитать и обновить во время синхронизации, включая
повторное открытие интерфейса. Фоновые обновления прогресса не очищают карточки
и не запускают повторное измерение NAS каждую секунду.
